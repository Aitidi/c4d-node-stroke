# 集成调查

## 已确认

- 本机存在 Cinema 4D 2027 和 2027.0.0 C++ SDK。
- SDK 节点示例使用 `NodeMaterial::GetGraph`、图事务、`GraphNode::Connect` 和 `GraphModelHelper::GetSelectedNodes` 操作节点图。
- SDK 中 `nodes.framework/source/maxon/definitions/nodes_access.h` 中涉及 Node Editor 的 component access ports 被标注为 INTERNAL，不能当成稳定的公开扩展接口。
- Maxon 的旧版开发者论坛答复指出活动节点编辑器、其坐标及视图信息不可获取；该答复并非对 2027 的保证，需要继续核对当前版本。

## 尚待解决

1. 在 2027 中定位用户正在交互的编辑器及图、组上下文，处理多个编辑器和材质。
2. 获取视图变换、节点边界、端口和渲染连线形状，并捕获手势而不干扰默认行为。
3. 通过事务安全修改 Redshift 图，明确类型兼容、复合端口、现有连接、撤销和失败回滚。
4. 注册合法插件 ID，构建插件，并在 C4D 2027 / Redshift 中完成交互和撤销测试。

## 2027 原生节点画布调查（2026-10-28）

原生 Redshift 测试材质中，通过 `experiments/node_layout_probe.py` 只读查询 `widgetDataBlackBox`：两个顶层节点分别含 `((0,0),128)` 和 `((177,0),128)`。它是未公开数据，仅确认该场景中可读取节点位置与宽度；端口递归探针未发现相同属性。不同文档、组、多个节点编辑器和布局变化均尚未验证。

Maxon 关于节点呈现器的说明：https://developers.maxon.net/forum/topic/15424/how-to-set-the-position-of-a-node-manually 。节点位置与视图显示由非公开的 presenter 管理。要在原生画布做可靠切线，仍需实际编辑器视图上下文、屏幕变换、端口位置及曲线、裁剪和输入接管，不能把节点位置直接当作屏幕坐标。读取到的数据也不是稳定的公开 API。

独立画布实现已移到 `experiments/independent_canvas.cpp`，并从正常插件构建中移除。上一轮安装的二进制仍含该实验命令，直到 C4D 退出后替换为本轮重新构建的插件；当前尚无原生手势实现。

## 原生视图读取验证（C4D 2027.0 Windows，Redshift）

- 测试材质根节点 `widgetDataBlackBoxOut` 是嵌套 `DataDictionary`，C++ 实测外层键示例 `net.maxon.mvp.serializationV2_0.blackbox.graph.0`，内层数据可按 `Tuple<Float32, Vector2d32>` 读取。
- 一个已打开的视图：平移前 `(0.784, (323.666, 370.096))`；滚轮平移后 `(0.784, (323.666, 770.096))`，节点屏幕位置相应移动约 400 像素。缩放后另一次读取为 `(1.0, (156.151, 7.5))`。该实验说明数值与视图变化相关，并非全面证明在所有布局或 DPI 下的变换。
- 测试节点位置 `(0,0)`、`(284.697,2.692)`，缩放 0.784 时屏幕水平间距约 223 像素，与 284.697 × 0.784 一致；缩放 1 时约 285 像素。
- C++ `native_layout` 已在实际测试材质的根节点及两个节点上只读成功；读取器限制 2027.0，检查数据类型和有限值。它不声称已找到当前窗口对应的记录，未接管输入或修改图。
- 相同图中可以保留多个记录。通过孤立视图操作前后差分可以识别唯一变动的记录，但不能假定其顺序就是活动窗口；多个记录变化、重复或缺失时必须拒绝。`src/view_tracking.*` 只实现此差分逻辑，尚未接到宿主 UI。
- 双窗口受控实验：用编辑器右上角新建第二个实例，两个窗口显示同一 Redshift 材质。初始记录分别为 `(1, (249, 275.5))`、`(1, (247, 274.5))`；仅缩放第二个窗口后变成 `(1, (249, 275.5))`、`(0.774, (217.672, 221.146))`，第一个窗口画面仍为原缩放；再仅缩放第一个窗口，记录变为 `(0.774, (219.221, 221.92))`、`(0.774, (217.672, 221.146))`。这验证了该场景中两个视图分别更新记录，不证明记录索引在重开、锁定其他材质、嵌套组或布局切换后稳定。
- 待完成：原生画布窗口与记录的绑定、画布原点及 DPI、端口可见状态和位置、实际曲线命中、手势捕获及主线程事务、撤销和复杂图测试。

## Windows 画布窗口与输入观察（C4D 2027.0）

- 只读窗口探针在停靠的 Redshift 节点编辑器中找到一个可见 `Static` 子窗口，其屏幕矩形与画布吻合：主窗口最大化时为 `(40,157,1261,1041)`；恢复并移动主窗口后为 `(208,255,1093,871)`，对应画布随之移动和缩小。新建浮动编辑器时也出现了一个对应画布的可见 `Static` 子窗口。
- 单次画布点击的 `WM_LBUTTONDOWN` / `WM_LBUTTONUP` 目标句柄与窗口枚举中画布子窗口句柄相同；在同一 UI 线程安装的 `WH_GETMESSAGE` 只读探针观察到了这些消息，并通过 `CallNextHookEx` 原样传递。探针手动关闭后不再观察输入，插件卸载时也卸载钩子。
- 这只验证了一个停靠布局和一个浮动布局。`Static` 是通用系统窗口类，不能仅凭类名把它认定为节点画布，更不能仅凭窗口句柄判断材质、图或视图记录。还需验证其他布局、3D 视图、多个不同材质、捕获和 DPI；点击消息观察也不等于已经实现可用手势拦截。
- 在宿主二进制的字符串中可见 `GetNodeGraphPresenter`、`GetCanvas`、`GetWidgetHitMap` 和 `ObservableMouseHitTest` 等内部方法名称。它们不是 SDK 中已公开的调用接口，目前没有验证其 ABI 或调用入口。
